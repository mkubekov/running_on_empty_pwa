# Почти на нуле — практикум

PWA для ежедневной практики по книге Jonice Webb «Running on Empty»
(рус. изд. «Почти на нуле»). Книга описывает Эмоциональное Игнорирование и даёт
набор упражнений и бумажных «Листов Изменений», которые нужно вести неделями.
На бумаге это разваливается: нет напоминаний, нет истории, словарь эмоций на
сотни слов неудобно листать. Приложение переносит практикум в телефон.

**Книга в комплект не входит** и приложение её не заменяет — как и терапию.

## Что внутри

| Модуль | Откуда |
|---|---|
| **Лист эмоций** — запись чувств несколько раз в день, с гайдом по шести шагам «Упражнения на идентификацию и именование» | Глава 6 |
| **Словарь эмоций** — 38 категорий, 797 слов, поиск и свои слова | Ресурсы для восстановления |
| **ИППП** — мастер из четырёх шагов: Идентифицируй → Прими → Припиши → Примени | Глава 6 |
| **Листы Изменений** — «Говорю "нет"», «Прошу о помощи», «Программа Трёх Дел» | Глава 7 |
| **Опросник** — 22 пункта, с возможностью пройти заново и сравнить | Начало книги |
| **«Я сбился»** — экран возврата к практике без упрёков | Глава 5 |

Остальные шесть Листов Изменений описаны в `src/content/trackers.ts` и помечены
`implemented: false` — движок уже умеет рисовать листы по типу, дело за
компонентами для `list`, `scale` и `habit`.

## Принципы, заложенные в интерфейс

Автор прямо предупреждает: изменения идут «два шага вперёд, один назад»,
а самокритика и уклонение — главные враги прогресса. Поэтому:

- **никаких стриков, которые сгорают**, и никаких «вы пропустили 3 дня»;
- пустой день в истории — просто пустой день, он ничего не обнуляет;
- **максимум два активных навыка**, интерфейс не даст включить третий;
- любой Лист Изменений можно переписать под себя — автор настаивает, что
  универсального шаблона тут быть не должно.

## Оформление: тетрадь

Практика из книги — это бумажные «Листы Изменений», которые заполняют от руки.
Отсюда визуальный язык: каждый раздел — **обведённая графа бланка** с названием,
врезанным в рамку, так что границы разделов видно сразу. Внутри графы строки
разделяет **линовка**, а слева идёт узкое поле для приписок: время записи, счёт
отказов, номер главы. Скруглённых боксов в интерфейсе нет ни одного.

Счётчик в листах изменений рисуется **палочками**, как считают на полях: четыре
и пятая поперёк.

Два шрифта с разведёнными ролями: **Literata** — то, что пишет человек (слова
эмоций, заметки, цитаты из книги); **Golos Text** — то, что «напечатано в
тетради до тебя» (подписи, кнопки, приписки на полях).

Тяжёлые и светлые состояния окрашены как **две равноправные чернильницы** —
фиолетовые чернила и сепия. Это не светофор: книга прямым текстом говорит, что
плохих эмоций не бывает, поэтому цвет не может подсказывать, какое чувство
«правильное».

Шрифты лежат локально (`public/fonts`, 280 КБ) — приложение обязано
открываться без сети. Пересобрать: `python scripts/fetch-fonts.py`.

## Приватность

Дневник живёт **только в браузере** (IndexedDB) и никуда не отправляется.

Напоминания устроены так, чтобы это не нарушать: на сервер уходит адрес
доставки push-уведомления и окно, в которое его присылать — и всё. Само
уведомление приходит **без содержимого**, текст к нему подбирает service worker
уже на устройстве. Сервер физически не может ничего рассказать о вашем
состоянии, потому что ничего о нём не знает.

## Как приходят напоминания

Точных времён нет намеренно: ровно в 14:00 каждый день — это будильник, на
который перестаёшь реагировать. Вместо этого задаётся **окно** (например
с 09:00 до 22:00), **сколько раз в день** и **минимальный промежуток** между
напоминаниями. Конкретные моменты разыгрываются случайно внутри окна, заново
на каждый день.

Промежуток нужен, чтобы случайность не слепила два подряд. Интерфейс сам
считает, сколько напоминаний помещается в окно с выбранным промежутком, и не
даёт выбрать больше: окно 09:00–22:00 при промежутке в три часа вмещает
максимум пять.

Математика расписания лежит в `shared/schedule.ts` и используется обеими
сторонами: браузер по ней показывает, во сколько сегодня придут напоминания,
воркер по ней же решает, когда слать. План на день разыгрывается один раз и
хранится в KV, поэтому повторные запуски крона не шлют дублей.

Обратная сторона: очистка данных сайта стирает дневник. В «Настройках» есть
выгрузка и загрузка JSON — загрузка **сливает** данные, а не затирает их.

## Стек

- Vite + React 19 + TypeScript, Tailwind CSS v4
- Dexie (IndexedDB), react-router, date-fns
- `vite-plugin-pwa` в режиме `injectManifest` — свой service worker ради `push`
- один Cloudflare Worker: раздаёт статику, держит API и крутит cron-триггер

Почему Cloudflare, а не Vercel: на бесплатном тарифе Vercel cron запускается
раз в сутки, чего не хватит для нескольких напоминаний в день. У Cloudflare
шаг от минуты, KV бесплатен, а `assets`-биндинг позволяет держать статику и
крон в одном проекте.

Почему PWA, а не Telegram Mini App: на Android Web Push работает нативно,
а мини-приложение потребовало бы бота и увело бы личный дневник в мессенджер.
Канал напоминаний вынесен за интерфейс `ReminderChannel`
(`src/reminders/channel.ts`) — если понадобится телеграм или iPhone, меняется
только реализация.

## Запуск

Пошаговая инструкция — в [ЗАПУСК.md](ЗАПУСК.md): локальный запуск, деплой на
Cloudflare с уведомлениями, установка на телефон и что делать, если пуш не
дошёл.

Коротко:

```bash
npm install
npm run dev        # посмотреть локально
npm run deploy     # собрать и выложить
```

## Данные из книги

`src/content/emotionWords.generated.ts` собирается из PDF вашего экземпляра:

```bash
python scripts/extract-emotions.py "путь/к/книге.pdf"
```

Зависимостей у скрипта нет — PDF разбирается стандартной библиотекой Python.
Сам PDF в репозиторий не коммитится (`.gitignore`).

Словарь в репозиторий **не входит**: 797 слов — это прямая выжимка из
приложения к книге, и распространять её вместе с кодом неправильно. В
`.gitignore` он есть, а вместо него лежит `emotionWords.example.ts` — небольшая
самостоятельная подборка на 8 групп. Перед сборкой `scripts/ensure-emotions.mjs`
подставит её, если полного словаря нет, так что клон собирается и работает
сразу. Существующий полный словарь скрипт не трогает.
